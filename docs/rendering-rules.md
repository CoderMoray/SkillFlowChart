# SkillFlowChart 渲染规则

> 本文件定义流程图渲染引擎的不可违背原则。
> 所有功能增强、bug 修复、算法优化都必须遵守这些规则。
> 违反规则的方案不予采纳。

---

## 一、职责分离

### 规则 1：AI 决定拓扑，脚本决定几何

- AI（或用户）通过 nodes.json 定义：节点列表、边列表、边的 side 属性、回环
- 脚本负责：depth 计算、cx/cy 坐标、连线路由、SVG 渲染
- 脚本不得从标签文字推断语义（如从 "是/否" 推断分支方向）
- 节点位置不由连线路径驱动

## 二、布局

### 规则 2：连线不可穿透节点

一条边的视觉路径（水平段 + 垂直段）不得穿过任何非 source/destination 的节点的边界框。

- 当直线路径会穿透节点时，必须绕行
- 绕行优先向下偏移（增加 y 间距），而非缩短节点间距
- 不得为了绕行而移动节点位置
- 如果所有绕行路径都与其他节点冲突，宁可增加层级间距使图变高

### 规则 3：只用直角折线

所有连线必须由水平段和垂直段组成，不允许出现斜线。

- 判定标准：任一线段的 x1≠x2 且 y1≠y2 即为斜线
- 诊断脚本通过解析 SVG line 元素检测斜线

### 规则 4：节点不可重叠

同层节点的边界框不得有任何像素重叠。

- 防重叠是布局的最后防线，不是常规手段
- 当拓扑导致同层 cx 冲突时，按预设 slot 错开
- slot 满时向右侧外推
- 碰撞检测用两个节点实际半宽之和，不使用固定估算值

### 规则 5：决策侧支的深度语义

决策节点（type=decision）的 left/right 出边：
- 目标也是 decision → 同层侧支（side_targets）
- 目标是 process/output/terminal → 下一层（bottom 语义）

这条规则确保 "检查→处理→检查" 链路不会把 process 和 decision 挤在同一层。

## 三、连线路由

### 规则 6：三类路由模式

| 模式 | 适用场景 | 路径 |
|------|---------|------|
| vertical | src.cx == dst.cx | 直线向下 |
| horizontal | 决策侧支，同层 | 水平连线（带 label 弧线） |
| fork | src.cx ≠ dst.cx | 垂直→水平→垂直 三段折线 |

### 规则 7：汇合路由

多条入边到同一节点（汇合点）时：
- 使用三段式路由（垂直→水平→垂直），水平段在不同 y 高度错开
- 入边来源的 cx 相同时，按固定偏移量水平错开
- 入边来源的 cx 不同时，按 cx 排列分配水平段 y

### 规则 8：回环路由

回环（loops）使用虚线，路径为 left_edge：
- 从 source 左侧出发，垂直向左，向上，再水平回到 target 左侧
- 回环不得在 edges 中重复声明

## 四、渲染

### 规则 9：自包含 HTML

输出是单一 HTML 文件，零外部依赖：
- SVG 内联
- 使用系统字体栈（无需嵌入字体文件）
- 无 JavaScript
- 无 CDN 引用

### 规则 10：三主题一致性

light / dark / transparent 三套主题只改变配色，不改变：
- 节点位置（cx, cy）
- 连线路径
- 布局结构
- viewBox 尺寸

### 规则 11：诊断标准

回归测试的三项硬指标，任何一项非零即为 FAIL：
- diag（斜线数）= 0
- zero（零长度线数）= 0
- overlap（重叠节点数）= 0

未来可增加：
- cross（穿透节点数）= 0
